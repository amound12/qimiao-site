# 日常维护手册

> 服务器上的日常四件事：更新、备份、恢复、看日志。所有操作都在 `/opt/qimiao` 目录下进行。

## 一、更新代码（发布新版本）

```bash
cd /opt/qimiao
git pull
docker compose -f deploy/docker-compose.yml up -d --build
```

（做什么：拉最新代码 → 重建镜像 → 平滑替换容器。整个过程约 30 秒~2 分钟，期间旧容器继续服务到新容器就绪。）

验证：

```bash
docker compose -f deploy/docker-compose.yml ps    # running
curl -s http://127.0.0.1:8000 >/dev/null && echo OK
```

> 注意：数据在 `./data` 目录（Docker 挂载），**更新代码不碰数据**，放心更新。

## 二、回滚到上一版本

一条命令（做什么：checkout 上一个 git tag → 重建容器。数据不受影响）：

```bash
cd /opt/qimiao
bash scripts/rollback.sh
```

它会先告诉你「从哪个版本回滚到哪个版本」，等你确认 y 才执行。

手动回滚到指定版本（比如回到 v0.1.0）：

```bash
cd /opt/qimiao
git checkout v0.1.0
docker compose -f deploy/docker-compose.yml up -d --build
```

回到最新版：`git checkout main && git pull && docker compose -f deploy/docker-compose.yml up -d --build`

## 三、备份

手动备份（做什么：把 `data/`（全部数据库）+ `.env` 打包到 `backups/`，只保留最近 14 份）：

```bash
cd /opt/qimiao
bash scripts/backup.sh
```

自动每天备份（做什么：用 crontab 定在每天凌晨 3:00 执行）：

```bash
crontab -e
```

在文件末尾加一行并保存：

```
0 3 * * * cd /opt/qimiao && bash scripts/backup.sh >> backups/cron.log 2>&1
```

## 四、恢复

（做什么：把某个备份包解回来。**会覆盖现有数据，先看说明**）

> ⚠️ 危险点说明：解包会覆盖 `data/` 目录里的现有数据库。如果现在线上数据比备份新，
> 覆盖就丢了。稳妥流程是「先停容器 → 恢复 → 再启动」。

```bash
cd /opt/qimiao
docker compose -f deploy/docker-compose.yml down        # 1. 停止容器
tar -xzf backups/qimiao-20260925-030000.tar.gz          # 2. 解开备份（覆盖 data/ 和 .env）
docker compose -f deploy/docker-compose.yml up -d       # 3. 重新启动
```

## 五、迁移到新服务器

```bash
# 旧服务器：打个最新备份
cd /opt/qimiao && bash scripts/backup.sh
scp backups/qimiao-最新时间戳.tar.gz root@新服务器IP:/opt/

# 新服务器：按《部署手册.md》走完第 1~6 步，然后：
cd /opt/qimiao
tar -xzf /opt/qimiao-最新时间戳.tar.gz
docker compose -f deploy/docker-compose.yml up -d --build
```

## 六、看日志

| 想看什么 | 命令 |
|---|---|
| 站点日志（访问报错、模块加载） | `docker compose -f deploy/docker-compose.yml logs -f` |
| 只看最近 100 行 | `docker compose -f deploy/docker-compose.yml logs --tail 100` |
| Nginx 访问日志 | `tail -f /var/log/nginx/qimiao.access.log` |
| Nginx 错误日志 | `tail -f /var/log/nginx/qimiao.error.log` |

## 七、常见问题排查

**容器起不来 / 一直重启**
```bash
docker compose -f deploy/docker-compose.yml logs --tail 50
```
最常见的三种：`.env` 语法错了（少了 `=` 后面的值）、`data` 目录权限问题、代码没拉全。看日志第一行报错。

**80 端口被占用（Nginx 起不来）**
```bash
ss -tlnp | grep :80        # 看谁占了
systemctl stop apache2 && systemctl disable apache2   # 通常是 Apache，装过的话直接停掉
systemctl restart nginx
```

**磁盘满了**
```bash
df -h                      # 看磁盘占用
du -sh /opt/qimiao/*       # 看项目里谁最大（正常应该是 backups 和 data）
```

> ⚠️ 清理 Docker 无用镜像会删掉**当前没在用的所有镜像**，确认容器都在跑再执行：
> ```bash
> docker system prune -f
> ```

**想临时关闭整站**
```bash
cd /opt/qimiao && docker compose -f deploy/docker-compose.yml down
# 重新上线：up -d
```

**数据库坏了想从头再来**
> ⚠️ 会删掉该模块全部数据。删哪个模块的 db 文件就重置哪个模块，其他模块不受影响：
> ```bash
> cd /opt/qimiao && docker compose -f deploy/docker-compose.yml down
> rm data/todo.db              # 只重置待办模块
> docker compose -f deploy/docker-compose.yml up -d
> ```
