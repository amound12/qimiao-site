# 部署手册 · 宝塔面板版（阿里云）

> 适用场景：阿里云 ECS + 已装好宝塔面板。
> 与《部署手册.md》（裸命令版）**二选一**。两版的差别只有一个：裸命令版用系统 Nginx，宝塔版用宝塔管理的 Nginx 建站反代。
> Docker 部分两条路完全一致——所以《日常维护手册.md》的更新/备份/回滚命令在这条路线上原样可用。

---

## 第 0 步：准备清单

- [ ] 阿里云 ECS（Ubuntu 22.04/24.04，1核1G 起），已装宝塔面板并登录
- [ ] 能 SSH 到服务器（宝塔面板的「终端」也行）
- [ ] （可选）域名，A 记录解析到服务器公网 IP

## ⚠️ 第 1 步：阿里云安全组放行端口（最容易漏的一步）

**宝塔防火墙和阿里云安全组是两层独立的墙**——只在宝塔里放行没用，这是新手 502/打不开的头号原因。

去 **阿里云控制台 → ECS 实例 → 安全组 → 配置规则 → 入方向**，添加以下规则：

| 端口 | 授权对象 | 用途 |
|---|---|---|
| 80 | 0.0.0.0/0 | HTTP |
| 443 | 0.0.0.0/0 | HTTPS |
| 22 | 你的常用 IP（或 0.0.0.0/0） | SSH |
| 宝塔面板端口（如 8888） | 你的常用 IP | 面板（建议限 IP） |

然后在宝塔 **安全 → 防火墙**，同样放行 80 / 443。

## 第 2 步：安装 Docker

SSH 连上服务器（或用宝塔面板的「终端」），执行：

```bash
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker
docker --version && docker compose version
```

> 也可以在宝塔 **软件商店 → Docker管理器** 安装，效果一样（它底层就是装 Docker + compose 插件）。
> 如果 curl 超时（境外源慢）：`apt install -y docker.io docker-compose-plugin` 也能用。

**国内拉镜像慢/超时的解法（阿里云专属）**：阿里云控制台搜「容器镜像服务」→ 左侧「镜像加速器」，
每个账号有专属加速地址（形如 `https://xxxx.mirror.aliyuncs.com`）。按页面提示写入
`/etc/docker/daemon.json` 后 `systemctl restart docker`；或者直接在宝塔
**Docker管理器 → 配置 → 镜像加速** 里粘贴该地址。Dockerfile 已内置清华 pip 源，
构建时装依赖不会卡。

## 第 3 步：拿代码

（做什么：把仓库克隆到 `/opt/qimiao`）

```bash
apt install -y git
git clone https://github.com/amound12/qimiao-site.git /opt/qimiao
cd /opt/qimiao
```

> **GitHub 拉不动？** 两个备选：
> 1. 在本地电脑执行 `git archive --format=tar.gz -o qimiao.tar.gz HEAD`，然后用**宝塔的文件管理**上传压缩包到 `/opt`，再在 SSH 里解包：`mkdir -p /opt/qimiao && tar -xzf /opt/qimiao.tar.gz -C /opt/qimiao`
> 2. 或给 git 挂代理（如果你有）：`git config --global http.https://github.com.proxy http://127.0.0.1:代理端口`

## 第 4 步：配置 .env

```bash
cd /opt/qimiao
cp .env.example .env
nano .env     # 宝塔终端里用 nano；改完 Ctrl+O 保存、Ctrl+X 退出
```

首版保持 `MODULES_ENABLED=todo` 不动即可。

## 第 5 步：启动站点

```bash
cd /opt/qimiao
docker compose -f deploy/docker-compose.yml up -d --build
```

验证（STATUS 应为 running；curl 应输出 HTML）：

```bash
docker compose -f deploy/docker-compose.yml ps
curl -s http://127.0.0.1:8000 | head -5
```

> 出问题先看日志：`docker compose -f deploy/docker-compose.yml logs --tail 50`

## 第 6 步：宝塔建站 + 反向代理

（做什么：在宝塔里建一个站点，把 80/443 的流量转发给容器的 8000 端口）

1. 宝塔面板 → **网站 → 添加站点**
   - 域名：填你的域名（如 `qimiao.example.com`），没域名就填服务器公网 IP
   - PHP 版本：选 **纯静态**
   - 数据库：不创建
2. 建好后点站点 → **设置 → 反向代理 → 添加反向代理**
   - 代理名称：`qimiao`
   - 目标 URL：`http://127.0.0.1:8000`
   - 发送域名：`$host`
   - 保存并开启
3. 此时浏览器访问 `http://域名或IP` 应该已经能看到小站了

> 反代后若出现 502：先确认第 5 步容器在跑（`docker compose ps`），再看阿里云安全组和宝塔防火墙是否都放行了 80。

## 第 7 步（有域名才做）：HTTPS 证书

宝塔的招牌功能，比 certbot 命令还省事：

1. 站点 → **设置 → SSL → Let's Encrypt**
2. 勾选你的域名 → 文件验证 → **申请**
3. 申请成功后开启 **强制 HTTPS**

证书到期前宝塔会自动续期，不用管。

## 第 8 步：用宝塔「计划任务」做每日自动备份

宝塔 → **计划任务 → 添加任务**：

- 任务类型：**Shell 脚本**
- 任务名称：`奇妙小站每日备份`
- 执行周期：每天 凌晨 3:00
- 脚本内容：

```bash
cd /opt/qimiao && bash scripts/backup.sh
```

（做什么：每天自动把 `data/` 数据库 + `.env` 打包进 `/opt/qimiao/backups/`，只保留最近 14 份。宝塔任务日志里能看到执行记录。）

## 收尾检查清单

- [ ] 浏览器访问 `http(s)://域名或IP`，首页正常
- [ ] 导航进「待办」，能添加/勾选/删除
- [ ] 手机访问正常
- [ ] 随便访问个不存在的路径（如 `/xxx`）→ 贴纸风 404
- [ ] `docker compose -f deploy/docker-compose.yml ps` 显示 running

## 备选路线：宝塔 Python 项目管理器直跑（不推荐，但可用）

如果你坚决不想碰 Docker：宝塔 **软件商店 → Python项目管理器** → 添加项目，
选 `/opt/qimiao`、Python 3.11+、启动方式 uvicorn、端口 8000、自动安装 `requirements.txt`，然后同样走第 6~7 步反代。

代价：绕开了 Docker 化部署，《日常维护手册.md》里的更新/回滚命令全部失效，需要改用「git pull + 项目管理器重启」，
环境依赖也要手动维护。**除非服务器内存小到跑不动 Docker（<512M），否则不建议。**

## 宝塔环境常见坑速查

| 症状 | 原因 | 解法 |
|---|---|---|
| 站点打不开，SSH 里 curl 127.0.0.1:8000 正常 | 阿里云安全组或宝塔防火墙没放行 80/443 | 回到第 1 步两层都放行 |
| 反代 502 | 容器没起来 / 端口填错 | `docker compose -f deploy/docker-compose.yml logs --tail 50` 看报错 |
| SSL 申请失败 | 域名没解析到本机 / 80 端口不通 | 先 `ping 域名` 确认解析，再查安全组 |
| 备份任务没跑成 | 脚本里用了相对路径 | 用上面给的绝对路径写法 `cd /opt/qimiao && bash scripts/backup.sh` |
| 宝塔面板本身被锁外面 | 安全组没放行面板端口 | 阿里云控制台 → 安全组放行面板端口（或用阿里云 VNC 救援） |

日常更新、回滚、恢复数据的操作与《日常维护手册.md》完全一致（都在 SSH 里执行），宝塔不用参与。
